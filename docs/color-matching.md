# Цветовое сведение камер (MatchEngine)

Документ описывает математику модуля `src/color/MatchEngine.*`, `ColorScience.*`, `ColorCharts.*`
и выводы ночного аудита 2026-11-16. Старый код (`ColorMatching`, `ColorTuning`) оставлен только
для тестов совместимости и анализа кадра; расчёт поправок в GUI идёт через MatchEngine.

## 1. Что не так было в старом расчёте (найдено и исправлено)

| # | Проблема | Почему неверно | Как сейчас |

## 2. Модель

Все режимы сводятся к набору пар «измерено → цель» в **кодированном** RGB (0..1):

```
Pair { measured Rgb, target Rgb, weight, neutral }
```

Для каждого канала подбирается модель первичной коррекции камеры (группа 8 протокола):

\[ y = \bigl(x\cdot g + l\,(1-x)\bigr)^{2^{-\gamma}} \]

* `g` — gain (8.2), точная модель: камера умножает сигнал;
* `l` — lift (8.0), `γ` — gamma (8.1). Масштаб lift/gamma у Blackmagic **не документирован**; модель
  верна по знаку и монотонности, поэтому для lift/gamma нужна итерация (2–3 прохода «Захват → Применить»).
* Подгонка — взвешенный Левенберг–Марквардт с ридж-приорами к нулю (lift, gamma) и к 1 (gain).
  Lift подгоняется только при ≥ 2 различных уровнях, gamma — только при ≥ 3 (иначе система вырождена).
* Пары с клиппингом (> 0.98 или < 0.02) получают малый вес.
* Общий уровень выделяется как яркостно-взвешенный общий gain (0.2126/0.7152/0.0722), остаток — баланс.

### Перевод в параметры камеры

| Что | Через | Формула |
|-----|-------|---------|
| Баланс | CC Gain RGB | `gain_c ← gain_c · (g_c / g_Y)` |
| Баланс | ББ (1.2) | ищется K' так, что отношение белых Планка `W(K')/W(K)` ≈ требуемому R/B; tint из G-остатка, `kTintPerUnit = 0.006` (оценка, уточняется итерацией) |
| Уровень | CC Gain Y-общий | `gain_c ← gain_c · g_Y` |
| Уровень | усиление dB (1.13) | `ΔdB = 6.02·log2(g_Y_lin)` (через декодирование OETF), шаг 1 dB |
| Уровень | диафрагма (0.2) | `ΔAV = −log2(g_Y_lin)`, f = √(2^AV) |
| Насыщенность | 8.6 | отношение хромы (только если есть цветные пары) |

### Проверка разумности (`sanityWarnings`)

Предупреждение (и отдельное подтверждение при применении), если:
отношение gain вне 0.6–1.6, |Δlift| > 0.15, |Δgamma| > 0.35, |ΔK| > 1500, |Δtint| > 20,
|ΔdB| > 9, диафрагма > 1.5 ступени, насыщенность вне 0.7–1.4. Иначе — компактное подтверждение.

## 4. Синтетические тесты (`tests/tst_matchengine.cpp`)

`SimCamera` моделирует камеру: сцена в линейном свете → ББ (Планк) → CC lift/gamma/gain → OETF.

| Тест | Критерий (проверяется в тесте) |
|------|-----------|
| CIEDE2000 по эталонным парам Sharma et al. | совпадение до 1e-3 (2.0425, 27.1492) |
| Планк: монотонность, `estimateKelvin(4300K)` | ошибка < 30 K |
| Эталонная камера с ошибкой gain | после 1 прохода gain камеры вернулся к 1.0 ± 0.04 |
| Таблица, ошибка lift+gamma+gain | ΔE2000 после < 1.0 и < 25 % от исходного |
| ББ: камера на 5600K при свете 3200K | каждый шаг понижает K (знак), итог 3200 ± 200 K, нейтральная ошибка < 1.5 IRE |
| Несовпадение модели (кривая камеры ≠ модели) | ΔE после < 2.0 и < 30 % исходного; дальше итерациями |
| Авто-нейтрализация каста | каст < 40 % исходного и < 3 IRE |
| Серая карта (тёплая) | gainR вниз, gainB вверх; через ББ — K < 5600 |
| Sanity | малые поправки — без предупреждений, gain×2 + K+3000 — ровно 2 предупреждения |
| Поворот таблицы на 180° | определён (rot = 2), все 24 патча совпали < 0.01 |
| compose относительно текущих | текущие gain/gamma камеры сохраняются и домножаются |
| Авто: чёрный кадр (нет сигнала) | пар нет, есть пояснение — поправка не рассчитывается |
| Авто: цветной сценический свет без нейтралей | gain каждого канала в пределах 0.45–2.2 (оценка света ослабляется и ограничивается) |
| Авто: очень тёмная нейтральная сцена (~8 % кода) | gain 1.0–2.05 (факт 1.50 = +1 ступень) и пояснение «повторите захват» |

### Защита авто-режима (по результатам живого теста)

* чёрный/пустой кадр (< 1 % пригодных пикселей или средняя яркость < 3 %) → «нет сигнала», без поправки;
* доверие к оценке света = доля нейтральных пикселей / 10 % (не меньше 0.25); оценка возводится в
  эту степень (ослабляется к нейтрали) и ограничивается диапазоном 0.55–1.8 по каналу (≈ 2500–10000 K);
* уровень — не более ±1 ступени линейного света за проход (gain ≈ ×1.5 в кодированном сигнале);
  после живого теста (тёмная сцена давала gain ×2.1 за один проход) — для эфира безопаснее
  несколько проходов.

## 5. Ограничения и риски

* Масштаб lift/gamma камер Micro Studio 4K G2 не документирован — первая поправка может быть
  неполной, делайте 2–3 прохода. Gain и ББ — предсказуемы.
* `kTintPerUnit` — оценка; tint сходится итеративно.
* Камеры с включённым авто-ББ/авто-экспозицией будут «бороться» с поправкой — выключайте авто в камере.
* Признак «без Camera Control» в списке входов: на ATEM Mini `DoesSupportCameraModel()` (выбор
  модели VISCA/PTZ) возвращает FALSE для HDMI-входов, хотя CCU по HDMI работает. Теперь любой
  обычный внешний вход пульта с Camera Control считается управляемым; DIR (ExternalDirect) — нет.
* Если чтение текущих значений не удалось (нет Camera Control на входе), поправка отсчитывается от
  заводских значений — в таблице выводится предупреждение.
